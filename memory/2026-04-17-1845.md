Why not it is automatic and work when needed so all skils are auto not manual
assistant: Because skills are essentially plug‑in code that runs on your machine, OpenClaw treats them the same way it treats any executable that could affect your system:

* **Security first** – Automatically pulling and executing arbitrary code could introduce malware, unwanted network access, or privilege‑escalation bugs. By requiring an explicit install step, you (and the system) get a chance to vet the skill, check its permissions, and confirm it’s from a trusted source.

* **Predictable resource use** – Skills may bring in large dependencies, need compiled binaries, or require specific system libraries. Installing them only when you ask avoids unnecessary disk‑space growth, network traffic, and runtime overhead.

* **Version control** – When you manually install a skill you know which version you’re using. Automatic upgrades could silently change behavior, break scripts, or introduce regressions.

* **User intent** – Some skills are very niche (e.g., a PDF‑editor, a search‑engine aggregator). Auto‑installing every available skill would clutter the workspace and make it harder to understand what’s actually available.

If you want the experience of “just‑in‑time” skill loading, you can set up a lightweight automation:

1. **Add a heartbeat rule** – Put a task in `HEARTBEAT.md` that runs `clawhub sync` (or `clawhub update`) on a regular interval. This will automatically pull updates for any skills that are already installed, without adding new ones without your consent.

2. **Create a short script** – Write a tiny wrapper (e.g., `auto‑install.sh`) that reads a list of desired skill slugs from a config file and runs `clawhub install <slug> --no‑input` for any that are missing. You can then call that script from a heartbeat or from a manual “install‑all‑my‑skills” command.

3. **Enable vetting** – Keep the `skill‑vetter` skill in the workflow so that every new skill is automatically scanned for risky permissions before the script actually installs it.

In short, the manual step is a deliberate safeguard. You can automate the *update* part safely, but the initial *install‑and‑vet* step should stay under explicit user control. Let me know if you’d like help wiring up a heartbeat‑based sync or a simple auto‑install script.
