assistant: I’m afraid the **self‑improvement** skill can’t be kept running as a forever‑alive background process – it’s designed as an **event‑driven hook**. ### What we *can* do instead

If you really want a continuously‑running check that periodically runs the self‑improvement routine (for example, to sweep the logs for missed learning events or to force a heartbeat‑style audit), you can set up a **cron job** that invokes the skill on a schedule. Here’s how to do it:

---

## Step‑by‑step: Create a self‑improvement cron that runs every 5 minutes

1. **Create a tiny wrapper script** in the workspace (this just calls the self‑improvement skill).

   ```bash
   cat > /root/.openclaw/workspace/run-self-improvement.sh <<'EOF'
   #!/usr/bin/env bash
   # Invoke the self‑improvement skill on demand
   openclaw sessions_spawn \
     --runtime subagent \
     --mode run \
     --label SelfImprovementCron \
     --task "Run self‑improvement audit (no‑op if nothing to log)" \
     --model openrouter/openai/gpt-oss-120b:free \
     --thinking adaptive
   EOF

   chmod +x /root/.openclaw/workspace/run-self-improvement.sh
   ```

2. **Add the cron entry** (using OpenClaw’s built‑in `cron` command so it’s managed by the same service).

   ```bash
   # This creates a cron that runs the wrapper every 5 minutes
   openclaw cron add \
     --schedule "*/5 * * * *" \
     --command "/root/.openclaw/workspace/run-self-improvement.sh" \
     --label self-improvement-5min
   ```

   - `--schedule "*/5 * * * *"` = every 5 minutes.
   - `--label` gives you an easy name to manage or remove the job later.

3. **Verify the cron is registered**

   ```bash
   openclaw cron list
   ```

   You should see an entry like:

   ```
   self-improvement-5min  */5 * * * *  /root/.openclaw/workspace/run-self-improvement.sh
   ```

4. **What the cron actually does**

   - Every 5 minutes it spawns a short‑lived sub‑agent (just like the automatic hook does).
   - If there’s nothing to log, the self‑improvement skill will simply exit with no changes – it’s harmless.
   - If any pending learning entries exist (e.g., from a previous failure that wasn’t captured), the skill will process them and write the appropriate markdown files.

5. **Optional: Adjust the interval**

   If you want it tighter (e.g., every minute) or looser (hourly), change the `--schedule` argument accordingly. Cron syntax follows standard POSIX rules.

---

### Why this is the safest approach

- **No permanent process**: The cron launches a fresh sub‑agent each run, which then terminates – exactly how OpenClaw’s architecture expects background work.
- **Keeps the gateway responsive**: A continuously running sub‑agent would tie up the gateway’s resources and could interfere with real user requests.
- **Still “always on”**: By running every few minutes, the self‑improvement logic is effectively always available, and any missed events will be caught on the next tick.

That removes the scheduled job without touching the underlying skill.
